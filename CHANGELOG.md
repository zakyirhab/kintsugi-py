## [0.4.0] - 2026-10-30

### ⚠️ Breaking Changes
- **Default `idempotent=False`**: Functions are now treated as non-idempotent by default to prevent unintended side effects (e.g. re-executing credit card charges or non-idempotent database writes during dry-run validation). If your function is purely functional or read-only, explicitly pass `@heal(idempotent=True)`.
- **Strict AST Guardrails**: Patches generated by LLMs are parsed and strictly validated. Any forbidden language constructs (`global`, `nonlocal`, dynamic `type(...)` class creation, unauthorized builtins, or runtime filesystem access) cause immediate patch rejection and fallback.
- **`__builtins__` Filtered Environment**: Sandbox execution no longer inherits default CPython `__builtins__`. It executes inside an isolated dictionary containing only `SAFE_BUILTINS`. Functions like `breakpoint()`, `exit()`, `quit()`, `help()`, and `memoryview()` are completely inaccessible to generated code.

### 🚀 New Features
- **Exception Filtering (`heal_on`)**: `@heal(heal_on=(ValueError, KeyError))` allows restricting runtime healing to specified exception classes. Unlisted exceptions bypass LLM repair and bubble up immediately.
- **Explicit `SAFE_BUILTINS`**: Whitelisted safe builtins dictionary preventing log injection (`print` prefixed with `[KINTSUGI-PATCH]`) and restricted `__import__` allowing only whitelisted data modules (`math`, `re`, `json`, `datetime`, `collections`, etc.).
- **Fail-Closed Cold-Start Rehydration**: Cached disk patches are loaded with strict validation. If source code changes or placeholder secrets are migrated (e.g., moved to environment variables), the cache safely rejects stale patches and falls back to original code.
- **LRU Fast-Path TTL**: Double-checked lock with read-only timestamp TTL checks in propose mode avoids lock contention under high-concurrency workloads.

### 🐛 Bug Fixes
- **Package-Prefix Matching**: Package boundary check now strictly verifies `mod == pkg or mod.startswith(pkg + ".")`, preventing malicious sibling modules (such as `myapp_evil`) from leaking into sandbox namespaces.
- **Dynamic `type(*args)` and `type(**kwargs)` AST Detection**: Disallowed `ast.Starred` arguments and keyword expansion targeting `type()`, closing dynamic class creation bypasses.
- **Global & Nonlocal Statement Ban**: Explicitly rejected `ast.Global` and `ast.Nonlocal` nodes in AST visitors.
- **Disk Cache Secret Exposure**: Patches saved to disk cache store placeholder tokens instead of plain-text secrets, with metadata sanitizing original error messages.

### 🛡️ Security Enhancements
- **Prompt Injection Defense**: Runtime arguments are sanitized and truncated before inclusion in LLM repair prompts.
- **Anti-Exfiltration URL & Sink Validation**: Placeholders are strictly forbidden in URL positions, string concatenations (`+`), dictionary keys, and non-whitelisted method sinks (`request`, `send`).
- **Cache Poisoning Prevention**: Tamper-evident HMAC-SHA256 checksums bound to function name, AST fingerprint, and patch code prevent unauthorized modification of cached disk patches.

## [0.3.1] - 2026-10-30

### Added
- Multi-provider fallback chain supporting OpenAI, Anthropic, and Google Gemini with automatic failover.
- Propose-only execution mode (`mode="propose"`) with deduplicated patch proposals and cooldown timers.
- HMAC-SHA256 signed patch cache with AST structural fingerprinting.
- Reversible memory-only secret placeholders and regex scrubbing for sensitive runtime values.

---

## [0.3.0] - 2026-10-29

### Added
- Self-healing `@heal` decorator for synchronous and asynchronous Python functions.
- In-memory hot-swapping of healed function callables without process restarts.
- Initial AST sandbox verification for generated code.
